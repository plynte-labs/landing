# Contributing to Plynte Labs

Thank you for helping improve Plynte Labs. Keep contributions focused, documented, and easy to review.

Gracias por ayudar a mejorar Plynte Labs. Mantené las contribuciones enfocadas, documentadas y fáciles de revisar.

## Quick path

1. Fork the repository.
2. Create a branch from the repository's default branch.
3. Make a focused change.
4. Run the available checks.
5. Open a pull request with context and verification notes.

## Standards

| Area | Expected practice |
|------|-------------------|
| Branches | Use short names such as `feat/liveaudio-card` or `fix/metadata-license`. |
| Commits | Use [Conventional Commits](https://www.conventionalcommits.org/): `feat:`, `fix:`, `docs:`, `chore:`. |
| Scope | Prefer small pull requests that reviewers can understand quickly. |
| Tests/checks | Run the repository checks before requesting review. For this repo: `pnpm run lint` and `pnpm run build`. |
| Language | Code, identifiers, and technical artifacts are written in English unless the repo explicitly requires another language. Public-facing organization docs may be bilingual. |

## Pull request checklist

- [ ] The change has a clear purpose.
- [ ] The README/docs were updated if behavior or setup changed.
- [ ] Relevant checks were run locally or in CI.
- [ ] The PR description explains what changed and how it was verified.

## Español rápido

- Creá ramas desde la rama default del repositorio.
- Usá conventional commits.
- Mantené PRs chicos y revisables.
- Documentá cómo verificaste el cambio.
